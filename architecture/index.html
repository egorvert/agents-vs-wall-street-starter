Component zoom-in

Every component has one job and a narrow output contract. That is what makes the system understandable, substitutable and measurable.

01

Grounded research

The implemented swarm consolidates the wider persona design into four fixed lenses—history, guidance, operating model, and demand/peers—plus a counterevidence pass. The intended bench separates ten core perspectives and routes conditional specialists only when material. Code rejects invalid metrics, periods, scales, quotes and near-miss line items.

Contract

Common evidence packet; coverage across history, guidance, operating bridge, external corroboration and expectations; no final value.

Fundamental feature layer

Structured analysis separates what happened from what may move the next result: comparable history, directional drivers, recent news and public anchors. Machine facts retain full evidence lineage; prose views stay compact.

Contract

Facts, context, news impacts and anchors—usable by both quant and reconciliation.

03

Backtestable quantitative forecaster

Deterministic methods operate only on comparable periods, then combine history and anchors into a base and range. Rounding-aware normalization accepts explicit source scales while rejecting unresolved conflicts. Any better model can replace this component by writing the same contract.

Contract

timeseries.json → ranges.json, with method and evidence lineage.

04

Bounded reconciliation

The first pass is blind to consensus; the second sees anchors and ranges. The model emits only direction, drivers and a delta. Unknown evidence references are dropped; without directional agreement and two valid sources, the anchor is retained.

Contract

Final value, anchor, applied delta, evidence, rationale and fallback tier.

05

Reliability and delivery

Each stage validates its inputs and outputs. Failures are logged and fall back per metric: combined call → range base → public anchor → seasonal estimate → last reported. A final contract gate blocks invalid delivery; the workbook writer touches forecast cells only.

03 / 06

The four decisions that define the approach

Files over shared memory

Agents coordinate through inspectable contracts, so stages can be replayed or replaced independently.

Models for judgment

Language models find salience and direction; deterministic code owns arithmetic and scale.

Anchor plus earned delta

The system begins from a defensible base and moves only when cited evidence survives explicit gates.

Evaluation over intuition

New features or architectures must improve point-in-time backtests before entering the live path.

bounded_delta = clamp(proposed_delta, allowed_delta_band)
final_value   = clamp(anchor + shrink × bounded_delta, forecast_range)

The model never emits the submitted level.

What changed—and why

The design became smaller as evidence accumulated. Complexity was retained only where it improved coverage or control.

ConsideredAdvantageDecision
Dynamic agent routing and multi-round debateFlexible research and opposing views.Replaced by fixed parallel specialists plus one counterevidence pass: easier to reproduce and less prone to social convergence.
Runtime web retrievalBroader, newer discovery.Excluded from the forecast path to preserve a provable cutoff and deterministic replay.
Large estimator committee and aggressive blendingPotential variance reduction and upside.Replaced by one blind/reveal judgment with strong anchor retention; historical evaluation did not justify unconditional complexity.
Automatic optimisation from realised resultsFaster self-improvement.Kept human-gated until the historical sample is large enough to separate improvement from overfitting.
05 / 06

Known limits

Research coverage can vary

Fixed specialists improve replayability, but unusual issues may fall between roles and agentic extraction can vary. Coverage reports, retries and fallbacks contain that variance; they do not eliminate it.

Ranges are safety rails, not calibrated probabilities

They bound magnitude using history and anchors; they do not yet claim statistical confidence without a larger event set.

Automated test depth is uneven

The quant core has unit and point-in-time tests. Research, analysis, reconciliation and orchestration rely more heavily on runtime contract gates; broader integration and repeated-model tests remain work to do.

The learning loop is only partly automated

Quant scoring, range diagnostics and event sensitivity are implemented. Full-pipeline ablations, feature attribution, experiment registry and automatic promotion remain future work.

Fallbacks still need admissible data

A total upstream outage cannot manufacture trustworthy values. Clear runs must start from clean state and treat any missing workbook as a delivery failure.

Corroboration is structural, not semantic

Distinct source files are required, but the system does not yet prove that sources are truly independent or that every quote entails the proposed delta.

06 / 06

Reproduce the run

Python 3.11+, pinned dependencies and a model API key are required. The first step preserves any prior outputs so stale artifacts cannot enter the run.

run_backup="run-backup-$(date +%s)"
mkdir "$run_backup"
if [ -d out ]; then mv out "$run_backup/out"; fi
find submission -maxdepth 1 -type f -name '*.xlsx' \
  -exec mv {} "$run_backup/" \;

python3 -m venv .venv
./.venv/bin/pip install -r requirements.txt
export OPENAI_API_KEY="…"

set -o pipefail
./.venv/bin/python pipeline/run.py --all 2>&1 \
  | tee "logs/final-run-$(date +%Y%m%d-%H%M%S).log"

npm install
npm run check:forecasts
